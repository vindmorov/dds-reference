# DDS Beta Flow — техническая спецификация MVP

## Цель

Помочь предпринимателю без финансового специалиста быстро понять, куда уходят деньги, увидеть динамику по категориям и определить, что требует внимания.

Ключевой результат первого опыта: пользователь загружает собственную выписку, разбирает сомнительные операции и находит хотя бы одну полезную зону внимания.

## Пользовательский маршрут

`Лендинг → Регистрация → Загрузка выписки → Вопросы о бизнесе → Импорт → Распределение → Проверка операций → Категории → Итог → DDS → Инсайт → Динамика → Действие`

Пользователь может перейти в DDS до полной проверки данных. В этом случае интерфейс показывает количество неразобранных операций и не скрывает их влияние на точность анализа.

## Маршруты и экраны

### Лендинг

Объясняет три ценности: структура денежных потоков, динамика категорий и подсказки по зонам внимания. Основной CTA — «Попробовать DDS».

### Аккаунт

Регистрация обязательна до загрузки файла, чтобы сохранить выписку, прогресс проверки, категории и результаты анализа.

### Загрузка

Поддерживаются собственный Excel/CSV и скачиваемый шаблон. Минимальные поля шаблона: `date`, `amount`, `description`, `counterparty`. Дополнительные поля — счёт, комментарий и исходная категория.

Для произвольного файла пользователь сопоставляет колонки с полями DDS. Ошибки должны указывать конкретную причину и способ исправления.

### Вопросы о бизнесе

Собираются: вид бизнеса, наличие других банков, наличие других юридических лиц и анализируемый период. Ответы используются для предложения направлений и категорий, но не должны блокировать импорт.

### Импорт и распределение

После загрузки система показывает прогресс, количество строк и период. Результат содержит всего операций, автоматически распределенные операции, операции с высокой/низкой уверенностью и нераспределенные операции.

### Проверка операций

Сомнительные операции сначала разбираются пошагово. Карточка содержит дату, сумму, назначение, контрагента, предлагаемое направление и категорию, а также уровень уверенности.

Действия: подтвердить, выбрать другую категорию, применить к похожим, пропустить. После пошагового режима доступна таблица для массового редактирования. Пропущенные операции не блокируют вход в DDS.

### Категории

Универсальная структура состоит из потоков «Поступления» и «Списания», внутри которых находятся категории и направления деятельности. Пользователь может подтвердить, переименовать, переместить, объединить, скрыть или создать категорию.

### Главный DDS

Первый уровень — три направления: операционная, инвестиционная и финансовая деятельность. Второй уровень — поступления и списания. Третий уровень — категории.

Простой режим показывает карточки, инсайты и понятную динамику. Табличный режим показывает месячные колонки, иерархию и подсветку изменения месяц к месяцу.

### Инсайты и категории

Каждый инсайт связан с одной или несколькими категориями. Переход ведёт к динамике категории, объяснению изменения и рекомендациям. Возможные действия: проверить операции, изменить план, добавить статью, создать резерв, отметить решённым или отложить.

## Состояния

Необходимо предусмотреть: новый пользователь, отсутствие данных, загрузку, ошибку формата, необходимость сопоставления колонок, импорт, наличие спорных операций, полностью обработанные данные, отсутствие инсайтов, неполный файл и повторный вход.

При повторном входе сохраняются файлы, прогресс проверки, структура категорий, прочитанные инсайты, отложенные операции и режим просмотра.

## Модель данных

```ts
type Flow = 'incoming' | 'outgoing';
type Activity = 'operating' | 'investment' | 'financial';

interface Transaction {
  id: string;
  date: string;
  amount: number;
  description: string;
  counterparty?: string;
  activity?: Activity;
  flow?: Flow;
  categoryId?: string;
  confidence?: number;
  reviewStatus: 'auto' | 'confirmed' | 'skipped' | 'unresolved';
}

interface Category {
  id: string;
  name: string;
  flow: Flow;
  activity: Activity;
  isCustom?: boolean;
  isHidden?: boolean;
}
```

## Компоненты

- `LandingPage` — ценность и вход в продукт;
- `AccountPage` — регистрация;
- `ImportPage` — файл, шаблон и сопоставление колонок;
- `BusinessContextPage` — вопросы о бизнесе;
- `ImportSummary` — результат обработки и уверенность;
- `TransactionReview` — пошаговая и массовая проверка;
- `CategorySetup` — настройка универсальной структуры;
- `DDSOverview` — главный экран;
- `ActivityPage` — направление с потоками;
- `CategoryDetailPage` — динамика категории;
- `InsightDrawer` — объяснение и действия по инсайту.

## Приоритет реализации

1. Модель операций, категорий и статусов проверки.
2. Загрузка шаблона и собственного Excel/CSV.
3. Сопоставление колонок и импорт.
4. Экран уверенности и проверка операций.
5. Универсальная настройка категорий.
6. Главный DDS с динамикой и инсайтами.
7. Детальная страница категории и действия.
8. Лендинг, регистрация и сохранение данных.
9. Опрос после первого анализа.

## Критерии бета-теста

Успешный сценарий: пользователь создал аккаунт, загрузил файл, увидел итог импорта, разобрал спорные операции, перешёл в DDS, открыл инсайт и просмотрел динамику категории.

Измеряем: успешную загрузку, долю автоматического распределения, время до первого инсайта, число разобранных операций, переходы из инсайта к действию, повторный вход и ответы на опрос.

Опрос после первого анализа содержит три вопроса: удалось ли понять, куда обратить внимание; насколько полезны инсайты по шкале 1–5; что помешало разобраться.

## Ограничения MVP

На первом этапе не требуются банковские интеграции, сложная ролевая модель, прогнозирование на основе ML или обязательная обработка всех операций. Основная задача — доказать ценность анализа на пользовательской выписке.
